# Business Performance Intelligence Platform

BPIP is an advisor-led business performance assessment and intelligence workspace. The architecture is intended to support the advisory firm first, with a path to multi-tenant SaaS and client collaboration later.

## Product principles

- Evidence before conclusions: distinguish verified facts, owner perspectives, advisor hypotheses, and validated findings.
- Deterministic calculations: financial formulas and scores are calculated by tested application logic, not generated by AI.
- Human review: AI can assist with synthesis and recommendations, while the advisor validates findings.
- Tenant isolation: client and engagement data must be scoped to the active organization.

## Stack

- Next.js 16 / React 19
- Vercel deployment
- Neon PostgreSQL
- Neon Managed Better Auth (passwordless email OTP)
- TypeScript

## Current alpha status

- Private advisor sign-in and protected routes implemented.
- Public registration disabled.
- First sign-in provisions the BPIP Advisory organization.
- Dashboard metrics are filtered to the authenticated user's organization.
- Sign-out implemented.
- Business management, assessment workflows, evidence intake, financial models, and reporting remain in development.

Do not store confidential client information in the alpha until tenant-level database policies, authorization checks for every read/write operation, audit coverage, and production email delivery have been completed and tested.

## Local setup

1. Install Node.js 22 or newer.
2. Copy `.env.example` to `.env.local`.
3. Set the three environment variables:
   - `DATABASE_URL`: Neon pooled PostgreSQL connection string.
   - `NEON_AUTH_BASE_URL`: Neon Managed Auth URL for the selected branch.
   - `NEON_AUTH_COOKIE_SECRET`: generate a unique secret of at least 32 characters.
4. Run `npm install`.
5. Run `npm run dev`.

## Deployment

The repository is connected to the Vercel project `bpip-advisor`. Pushes to `main` trigger deployments. Secrets are stored in Vercel environment variables and must never be committed to Git.

Neon's shared email delivery is suitable for initial testing only. Configure a dedicated SMTP provider before production client use.
